# Verification without a Dutch-speaking team

The pipeline combines source observations, constrained authoring, a different-vendor review, deterministic checks and independent source adjudication. **Agreement between models is not an estimate of truth.** Shared training material and shared dictionary errors create correlated mistakes. Record source families as well as product names: English, Dutch and Polish Wiktionary are not three independent dictionaries; wordfreq and SUBTLEX share lineage for some frequency material.

## Execution contract

1. **Acquire and pin.** Download a named snapshot; retain URL, byte count, SHA-256, schema/version, retrieval date and source-specific attribution. Parse to end and verify decompression/row counts before adoption. Partial files fail closed. Preserve original seed IDs and RU. Excerpts retain record hashes and locators in the saved excerpt set; a locator in an excerpt is not an original bulk-file line number.
2. **Select the sense.** Map lemma/POS and candidate sense to source definitions. Keep a human-readable Dutch definition, translation scope and reason for daily-life usefulness. NT2Lex `sense_se-id` joins ODWN **LexicalEntry.id**, not child Sense.id. Flag automatic mappings, homographs, reflexives, mass/count changes and source definition gaps. Freeze the candidate list before reporting coverage.
3. **Extract facts.** Use explicit ODWN WordForms articles, Kaikki gender/form/IPA fields, and source-aware mappings. Retain raw observations. Filter table labels, archaic/regional variants and form-of records; do not smooth a disagreement by majority vote. Spelling absence in OpenTaal is advisory, especially for productive compounds, phrases and names. A model may select a source-attested form but must not invent morphology/IPA.
4. **Model A authors a draft.** Supply the intended sense, selected evidence, learner PL/EN, target band, earlier concepts/scaffold, grammar prerequisites and fixed output schema. Generate NL examples and direct EN/PL translations, usage distinctions and optional hints. Do not add sources the author has not inspected. Preserve model/vendor/version when actually known, prompt hash, inputs and output hash. No runtime AI is introduced in the PWA or Android app.
5. **Validate deterministic contracts.** Validate JSON Schema, IDs and cross-links, content hashes, required locales, field-level provenance, article/POS compatibility, source existence, finite numbers, NFC/UTF-16 spans, separated verb segments, allowed forms and duplicate task contracts. Check that de/het alternatives are not mutually rejected and that mass plurals are not activated. Check vocabulary and grammar prerequisites separately. Structural pass does not confer language quality.
6. **Model B reviews independently.** Use Claude or another genuinely different vendor. Give B the evidence packet, context and rubric; omit A's confidence/verdict. B must judge each dimension and cite source record IDs. A subscription is an interaction route, not proof a review happened. Import the complete review response, vendor/model metadata, exact entry revision/hash and original response artifact. No live provider SDK is required in the repository.
7. **Resolve disagreements.** A source mismatch blocks the affected field. Reinspect the original dictionary table or retrieve an independent source such as an ANW entry or Taaladvies/Onze Taal note. Prefer explicit sense-qualified evidence to an extraction artefact. A can propose a revision; B must review the revised hash. Two unsuccessful revision cycles route to `flagged` with the disputed facts and concrete alternatives. A third model is a useful challenge, not a casting vote that can overrule source evidence.
8. **Compile by policy.** Only eligible task families enter a versioned curated pack. Preserve draft/flagged material for inspection and explicitly opted-in private use. No blanket entry approval from one passed field. Produce coverage and change reports; edits invalidate affected reviews. Rejected and superseded records remain traceable.

## Fixed reviewer rubric

For every dimension return `pass`, `revise`, `uncertain` or `not_applicable`, severity `critical|major|minor|none`, explanation, evidence record IDs and a concrete proposed correction when possible. The overall verdict is the worst required dimension; a numerical average cannot hide a wrong article or inverted meaning.

| Dimension                | Pass condition                                                                             | Typical blocking defect                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| Sense and scope          | NL definition, English and Polish refer to the same intended concept/construction          | Borrow/lend mixed; account meaning paired with bill example                   |
| Dictionary facts         | Article, forms, spelling and IPA match a cited, appropriate source; exceptions retained    | Model-only plural, discarded valid article, archaic form used as ordinary     |
| Dutch syntax/naturalness | Sentence is grammatical, idiomatic for declared region/register, and uses the target sense | Missing reflexive, bad separable order, wrong auxiliary                       |
| EN/PL translation        | Direct, natural and precise; person, number, tense, modality and scope retained            | Dutch half drie translated 3:30; pluralia tantum forced into wrong number     |
| Task ambiguity           | Cue selects the intended sense/form or acknowledges valid alternatives without penalty     | Several possible verbs but only target accepted in an open cloze              |
| Span/form contract       | Every required target segment is covered; non-target text is excluded                      | Particle omitted; reflexive included in one form but ignored in another       |
| Level and usefulness     | Estimate is plausible; everyday situation and prerequisites are explicit                   | Specialist noun presented as first-day universal vocabulary                   |
| Register and pragmatics  | Politeness, region and social use correctly scoped                                         | Informal farewell labelled formal; ordinary food labelled slang               |
| Hints and media          | Help is relevant, optional and accurately labelled; audio/image claims actually tested     | Invented etymology; image guesses abstract sense; untested audio marked ready |

## Status model

| Axis/status                                                                     | Meaning and permitted actor                                                                                                                                        |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Origin: `legacy`, `generated_draft`, `user_private`                             | Where content came from; never erased by later review.                                                                                                             |
| Structure: `unchecked`, `machine_checked`, `invalid`                            | Deterministic validator, tied to schema/tool version and payload hash.                                                                                             |
| Facts: `missing`, `source_verified`, `conflicted`, `not_applicable`             | Source verifier records an exact observation and scope. `source_verified` means supported by the cited observation, not independently proven correct.              |
| AI language review: `not_run`, `ai_reviewed`, `revision_requested`, `uncertain` | Only imported evidence of an actual different-vendor review can set `ai_reviewed`; author/self-check cannot.                                                       |
| Disposition: `draft`, `flagged`, `rejected`, `superseded`                       | Flags block affected tasks; rejection preserves archive history.                                                                                                   |
| Release: `blocked`, `eligible`                                                  | Computed for each task/locale against policy. All required structural, source and AI checks must pass on the current hash, with no unresolved critical/major flag. |

`language_reviewed` is deprecated. Legacy uses must migrate to explicit origin + review-evidence axes; do not relabel an unknown historic state as AI-reviewed or human-reviewed. A repository owner reviews the policy/software change, not each Dutch sentence. The shared family pack can be machine-curated under this ADR; private opt-in remains visibly provisional and cannot launder content into the curated channel.

## Estimating remaining error

Report denominators and strata. Track dictionary-field agreement separately for articles, plurals, tense forms, auxiliary/construction and IPA; mark missing and unassessable separately. Count unique lexemes/senses/source families to avoid treating five inflections or two mirrors as five independent confirmations. Report reviewer agreement before reconciliation, revision rates, severe defect rate, and unresolved rate. An agreement rate alone is **not** an accuracy claim.

For the pilot, review all 60 entries and every example with B, then re-check every high-risk category against another source where available. This session has no B responses, so inter-vendor agreement and residual language error are **unknown**, not 100% and not zero. The current 479/479 legacy form matches measure source surface support only; they exclude missing fields, auxiliary selection and sense correctness.

For larger releases, sample at the **entry/sense** level with a reproducible random seed. Suggested initial policy: a simple random sample of 300 release candidates plus a separate, fully enumerated risk sample (homographs, de/het alternatives, modal/perfect forms, reflexives/separables, idioms, Dutch-specific services, polysemy, PL false friends and source disagreements). Keep random and targeted results separate; oversampling risks without weights distorts overall estimates. If an actually independent, trustworthy adjudication found zero entry defects in 300 independent randomly sampled entries, the exact one-sided 95% upper bound would be `1 − 0.05^(1/300) ≈ 0.995%`. With 60 it is about 4.87%. These bounds apply to the adjudicated defect definition and detection process; they do **not** establish true correctness when the adjudicator is another fallible model or shares the same sources.

Use a third source-backed challenge review and deliberately seeded mutation cases to estimate reviewer sensitivity (wrong article, negation inversion, omitted reflexive, 2:30/3:30 reversal). Mutation detection measures sensitivity on those controlled cases, not all natural errors. Publish unassessable items and sensitivity limitations. Recheck all items affected by an importer bug, not only those that happened to be sampled. Never claim a measured final error rate without the sample, judgments and adjudication evidence.

## What actually ran here

All seed rows were screened by the authoring model; source excerpts were parsed and compared; 60 draft senses and 65 examples were authored; the deterministic delivery validator ran. `research/content-2026-10/review/reviewer-B-prompt.md`, request batches and response schema make the outstanding review concrete. Different-vendor review, Dutch TTS listening QA and empirical learner testing did not run. The compiler gate is therefore closed for this pilot. This is a complete research/implementation handoff with an explicitly unfinished linguistic release gate.
